1. Data and Shared Setup FOUNDATION

DoE starts with a blank design, while BO and SA begin by loading a CSV. Use one row per completed experiment and one named column per input or measured outcome.

  1. Load a CSV for BO or SADrag a .csv file onto the upload area or select it from your computer. EDOS uses the header row as the column names. On first load, the last column is treated as an objective and all earlier columns as features.
  2. Check feature and objective rolesIn Loaded Data, click the F / O control beneath a column name to switch it between Feature and Objective. This is essential if the last CSV column is not the measurement you wish to optimize or predict.
  3. Review or correct valuesCells in the loaded-data table are editable. Changes are used immediately by the current session; use Export CSV to save an edited copy. Clear All Data clears the dataset and resets the module configurations.

2. Design of Experiments (DoE) PLANNING

Use DoE to create a table of candidate experiments before you have data, or to create a controlled follow-up study.

Create a design

  1. Define factorsOn the Features tab, name each input, choose its type, and enter its range or levels. Use + Add Feature for each additional factor. At least two valid factors are required; Box-Behnken requires at least three.
  2. Add response columnsOn Objectives, add the outcomes you plan to measure, such as Yield or Purity. These appear as editable result columns in the generated table.
  3. Apply feasible-space rules when neededOpen Constraints to exclude impossible conditions. Numerical rules accept arithmetic comparisons such as Temperature + Pressure <= 180. Disallowed combinations exclude an exact combination of categorical levels, such as a catalyst/solvent pairing that cannot be used.
  4. Choose a design and run countIn DoE Tweaks, select a model and choose Max or Exact experiments when available. Click Create table of experiments to generate the matrix.
DesignBest suited to
Box-BehnkenResponse-surface studies with three or more factors; includes centre-point replicates.
Central CompositeFace-centred quadratic response-surface modelling and curvature checks within the entered factor bounds; includes centre-point replicates.
Fractional FactorialEfficient two-level screening at selectable Resolution III, IV, or V (or better).
Full FactorialEvery combination of the declared categorical, discrete, and regular levels; continuous factors use their lower and upper bounds. Supports mixed level counts. The natural run count is the product of the factor level counts.
Definitive ScreeningThree-level early-stage screening that estimates main effects independently of quadratic effects; two-level categorical factors are supported.
Latin Hypercube Sampling (LHS)Space-filling coverage with an exact user-selected number of runs.
D-OptimalA custom-sized, model-aware design. Select Linear, Interaction (2FI), or Quadratic order. The displayed run count is guidance: smaller designs are allowed, with a warning and zero D-efficiency when not all selected effects can be estimated.

Read the generated design

  • Orthogonality shows how independently factors vary; higher is generally better.
  • D-Efficiency indicates how efficiently the design estimates its intended model; higher is generally better.
  • Resolution reports Full factorial for a complete factorial grid, or the resolution of a complete fractional factorial design. Reduced designs show N/A because the original resolution is not guaranteed.
  • Curvature indicates whether the layout can represent nonlinear numerical responses. The first centre point is unique; subsequent repeats are highlighted and help estimate pure experimental error and lack of fit.

For all classical designs, including Full Factorial, a Max or Exact count below the natural size returns the requested number of runs and a reduction warning, even when too few runs remain to estimate all intended effects. Unique conditions take priority: repeats enter the table only after all unique conditions in the design are exhausted. A larger Max leaves the natural design unchanged; a larger Exact adds flagged repeats at the end. Quality metrics use the entire returned table, including repeats.

Algebraic constraints and disallowed combinations are supported for every design family, subject to the existing factor-type restrictions. Classical designs are filtered after mapping to executable factor levels, before any run-count reduction or replication. Exact-count requests may repeat surviving classical conditions; maximum-count requests do not add runs. Results identify the filtered design, excluded conditions, absent factor levels, removed centre points and the final model rank. Original resolution and curvature labels are not inherited by constraint-modified designs.

Constrained LHS uses reproducible candidate sampling and farthest-point selection, with finite-grid supplementation where applicable. It is labelled LHS-derived because strict stratification is not retained. If the bounded search cannot supply the requested number of distinct conditions, the result reports a shortfall without adding repeats. A failed bounded search is not proof that the experimental region is empty. D-Optimal retains its existing feasible-candidate selection. Unconstrained designs retain their previous Max/Exact behavior.

Full Factorial quality calculations assess main effects, two-factor interactions, and numerical quadratic terms for factors with at least three declared levels. Continuous bounds alone cannot assess curvature. Very large grids use a sampled candidate pool for reduced designs, disclosed in the warning; requesting more than 100,000 complete factorial runs requires fewer levels or a reduced count.

3. Bayesian Optimization (BO) OPTIMIZATION

BO learns from completed experiments and proposes a batch of promising new conditions. It is most useful after you have measurements for at least some experiments.

Configure and run

  1. Load data and set F/O rolesUpload your CSV, then verify the main-table column roles. In the BO Features tab, confirm the type, range, and Include checkbox for each input.
  2. Set optimization goalsOn Objectives, include the outcomes to optimize and choose maximize, minimize, or target. For target mode, enter the desired raw value. Importance values across included objectives automatically rebalance to 100%.
  3. Add constraints if requiredFeature constraints remove unphysical inputs before candidates are proposed. Objective Constraints add predicted raw-value boundaries, for example Purity >= 95, while optimizing another outcome. A feasibility notice means a candidate is not predicted to satisfy every objective boundary with high confidence.
  4. Choose the optimizer settingsChoose Gradient-based for continuous spaces or Exhaustive Grid (EDBO+) for enumerated settings. EDBO+ converts continuous features to a regular 10-step grid so every defined combination can be considered.
  5. Run and assessClick Run Bayesian Optimization. Review suggested experiments, model performance, plots, and objective values before committing a new campaign.
BO controlWhat it changes
Batch SizeHow many new conditions to propose for the next campaign.
AcquisitionFor one objective, choose EI or LCB. With multiple objectives, EDOS automatically uses a multi-objective strategy: equal importance explores the Pareto front; unequal importance prioritizes the weighted objectives.
Kernel FunctionThe model's smoothness assumption. Matérn 5/2 is the default; Matérn 3/2 is less smooth and RBF is smoother.
Exploration / Exploitation0 favours predicted best-known areas; 1 spends more suggestions learning uncertain areas.
NoiselessUse only when measurements have essentially no experimental variation.
No Re-evaluationPrevents suggestions that duplicate previously tested conditions. Turn it off only when repeat measurements are valuable.

Use the BO results

  • Suggested Experiments: feature cells and result cells are editable. Enter measured results after the lab campaign; the commit button activates when all outcome cells are numeric.
  • BO Model Performance: check R² and its Good / Limited / Poor status before relying heavily on interpolation. A poor result is a signal to gather broader or higher-quality data.
  • Outcome Estimator: enter a specific condition to receive predicted outcomes, uncertainty, per-objective success, global success, and any violated objective constraint.
  • Visualization: use Objectives Trend to inspect measured outcomes over the experiment order. Contour and 3D Surface views require two included numerical features; choose the axes, objective, resolution, and fixed values for all remaining features. Categorical features can be fixed, but not used as surface axes.
  • Pareto Front: with multiple included objectives, orange points are non-dominated trade-offs. The chart uses raw measurement units and can be exported as a CSV.
No new suggestion? If EDOS reports that all distinct conditions have been tested, increase exploration, switch kernel or acquisition, widen feature ranges, or allow re-evaluations.

4. Statistical Analysis (SA) INSIGHTS

SA uses the dataset to test predictive reliability and explain which inputs appear to drive performance. It runs as a progress-tracked job that can be cancelled with Abort.

  1. Select the analysis columnsLoad data, then use the SA Features and Objectives tabs to include the inputs and outcomes of interest. Target, importance, and optional objective constraints use the same meanings as BO.
  2. Choose a modelUse Linear Regression for simple, interpretable trends; Random Forest for nonlinear effects and interactions; or Neural Network (MLP) for more complex response patterns. Random Forest exposes Trees and Max Depth; MLP exposes Hidden Layers and Max Iterations.
  3. Run and validateClick Run the Statistical Analysis. Follow the progress panel, then inspect the Reliability & Validation table before interpreting detailed plots.

Understanding SA results

ResultHow to use it

Use Export Analysis Report to create a standalone interactive HTML report containing the active analysis and plots. The result cards also provide individual downloads for correlation, categorical analysis, parallel coordinates, feature importance, and SHAP values where applicable.

5. Exports, Imports, and Common Checks WORKFLOW

Move results between EDOS and the lab

  1. Export feature-only instructionsUse Export Features CSV in a DoE or BO result table when the lab only needs the proposed settings.
  2. Return measured outcomesEither type outcomes into the green result cells or use Import Results CSV. EDOS matches objective headers, including exports whose columns are labelled Objective (Result).
  3. Commit a completed campaignUse Add all to Main Dataset after every suggested row has numeric outcomes. The main dataset must contain matching feature and objective column names. EDOS then refreshes the data table and BO plots for the next iteration.
  4. Keep a recordUse the full Export CSV buttons for tables with both settings and results. Export the main dataset after direct edits if those changes should be retained outside the browser session.

Quick troubleshooting

  • Validation error for a feature: check the range syntax above and ensure each numeric lower bound is below its upper bound.
  • Constraint rejected: numerical rules must contain a comparison and use known numeric feature names; categorical exclusions need complete feature/value pairs.
  • Cannot commit results: fill every outcome cell with a number and check that the loaded main dataset has all matching column names.
  • Surface view unavailable: include at least two numerical BO features and one objective; set categorical variables as fixed values instead.
  • Weak model performance: treat recommendations and estimates cautiously, add informative experiments, or simplify the set of included features.
